# 타이틀·시스템 메뉴 추적 기록

v2.2부터 릴리즈 노트에 이렇게 적어 왔습니다.

> 타이틀 메뉴는 찾지 못했습니다. USRDIR 전 파일(0012 404MB 포함)에 텍스처
> 스트림이 없고, 실행 파일에도 Shift-JIS/UTF-8/UTF-16 어느 형태로도 문자열이
> 없으며, 스크립트에도 없습니다.

**이 진술은 두 군데가 틀렸습니다.** 아래에 무엇이 틀렸고 무엇이 실제로 확인됐는지 적습니다.

## 1. 실행 파일에 문자열이 있습니다

없던 게 아니라 **찾는 형태가 틀렸습니다.**

이 게임은 대사를 Shift-JIS로 저장하지 않습니다. 히라가나는 0x28부터 1바이트, 한자는 0x88~0x8D 선두의 2바이트로 폰트 슬롯을 가리킵니다. 메뉴가 같은 폰트로 그려진다면 저장 방식도 같을 텐데, Shift-JIS만 훑었으니 나올 리가 없었습니다.

게임 인코딩으로 찾으니 `BOOT.BIN`에서 바로 나왔습니다. `BOOT.BIN`은 암호화되지 않은 평문 ELF입니다(엔트로피 6.39, `EBOOT.BIN`은 8.00).

```
0x103700 부근   시스템 메시지
0x103000 부근   증거품 설명
0x107c00~0x115000  인물 메모, 증언, 사건 자료
```

해독한 예:

```
セーブされていませんがよろしいですか？
メモリスティックにセーブします。
すでにインストールデータが存在します。
上書きしてよろしいですか？
メモリースティックの空き容量が不足しています。
```

## 2. 가나표에 글자가 5개 빠져 있었습니다

처음 해독하니 「メモリスティックばセーブぜゃぞ。」처럼 가나가 어긋났습니다. 스크립트 해독기의 가나표가 `あ`부터 시작하는데, **게임 표에는 앞에 작은 모음 `ぁぃぅぇぉ`가 더 있습니다.** 넣으니 「ろをぜえぬぞぐ？」가 「よろしいですか？」로 정확히 풀립니다.

## 3. 한자는 아직 못 풉니다 — 그리고 왜 못 푸는지

`88 F5 88 F6` 두 글자가 `存在`여야 합니다(「インストールデータが存在します」). 그런데 **스크립트 폰트의 245·246번 글리프는 `妻`·`赤`입니다.** 짐작이 아니라 그려서 확인했습니다. `存`은 183번, `在`는 143번에 있습니다.

같은 선두 바이트에서 trail이 1 늘었는데 슬롯이 40 뒤로 뛰므로, **계산식이 아니라 대응표**입니다. 그래서 대응표를 찾았고, 없었습니다.

| 가설 | 검증 방법 | 결과 |
|---|---|---|
| 인덱스 → Shift-JIS 표 | Shift-JIS 한자 코드가 100개 이상 연속하는 구간 검색 | 0건 |
| 인덱스 → 폰트 슬롯 표 | 245→183, 246→143, 154→170, 334→190 을 동시에 만족하는 표 검색 (u8/u16/LE/BE) | 0건 |
| 바이트쌍 → 슬롯 표 | 183·143이 인접한 위치를 찾고 나머지 세 예측으로 검증 | 0건 |
| 두 번째 글리프 아틀라스 | 4bpp 글리프 형태 점수로 전 파일 스캔 후 육안 확인 | 후보 전부 코드·데이터 |
| 폰트가 1368자보다 길다 | 원본 stream1을 글리프 1368번 이후까지 렌더링 | 잡음 (폰트는 1368에서 끝남) |

## 4. 아카이브 0001~0004에도 스트림이 있습니다

이전 스캔이 **0x800 정렬만** 봤습니다. 0000이 거기에 스트림을 두기 때문인데, 이 파일들은 **0x800 + 0x40** 위치에 둡니다. 모든 탐침이 헤더에서 64바이트씩 빗나갔고, 그래서 "텍스처 스트림 없음"이 나왔습니다.

정렬을 고치니:

```
0001    276 스트림
0002    568 스트림
0003    126 스트림
0004      9 스트림
0011      0 스트림
```

압축을 풀면 stream0과 같은 모양의 u32 오프셋 표가 나옵니다. 다만 **헤더 배치가 다릅니다.** stream0은 record 0의 첫 워드가 크기표 위치인데, 이쪽은 거기가 0이고 0x40 위치에 (표 오프셋, 개수)가 들어 있습니다. 그 값으로 읽으면 아직 말이 되는 가로·세로가 나오지 않아, 컨테이너 해독은 미완입니다.

## 다음에 볼 곳

1. **0001~0004 컨테이너 헤더 확정.** 스트림은 열리고 팔레트(1024바이트)도 보이므로 남은 것은 크기표 배치뿐입니다. 가장 유망합니다.
2. **BOOT.BIN 역어셈블.** 메뉴를 그리는 함수가 글리프를 어디서 읽는지 따라가면 한자 출처가 나옵니다. 확실하지만 비쌉니다.
3. 한글 패치는 **한자 출처를 찾은 뒤**에야 가능합니다. 한글 글리프는 stream1 폰트에 넣어 두었는데, 메뉴가 그 폰트를 쓰지 않는다면 닿지 않습니다.

## 관련 도구

| 파일 | 역할 |
|---|---|
| `find_title.py` | 파일별 정체·엔트로피 판별 후 Shift-JIS 계열 검색 |
| `find_title_encoded.py` | 게임 인코딩으로 변환해 검색 (여기서 발견) |
| `decode_boot_text.py` | BOOT.BIN 구간을 게임 인코딩으로 해독 |
| `sweep_boot_text.py` | BOOT.BIN 전체에서 텍스트 구간 탐색 |
| `find_kanji_table.py` `find_remap.py` `find_pair_table.py` | 대응표 가설 세 가지 검증 (모두 0건) |
| `find_menu_font.py` `show_raw_glyphs.py` `show_glyph_range.py` | 두 번째 아틀라스 탐색과 육안 확인 |
| `scan_archives.py` | LZ11 스트림 스캔 (정렬 지정 가능) |
| `dump_archive_textures.py` | 0001~0003 컨테이너 해독 시도 (미완) |
