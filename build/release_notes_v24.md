취조 장면 한 대목에서 **대사가 한 줄씩 밀려 나오던 문제**를 고쳤습니다. 그리고 원문 글자표를 전수 검증해 이름 세 개를 바로잡았습니다.

## 적용 방법

```
certutil -hashfile "Enkaku Sousa Shinjitsu eno 23nichikan.iso" MD5
```

```
원본 크기   739,835,904 바이트
원본 MD5    9f9bb5eec3d2c37f184955b591923e1c
```

```
xdelta -d -s "Enkaku Sousa Shinjitsu eno 23nichikan.iso" Enkaku_Korean_v2.4.xdelta Enkaku_Korean.iso
```

```
결과 크기   739,835,904 바이트 (원본과 동일)
결과 MD5    9c3677f22900c0401e37ac1e8de738c5
```

이전 버전에서 갱신하는 경우에도 **원본 ISO에 적용**하십시오.

## 대사가 한 줄씩 밀려 나오던 문제

콘도 형사의 취조 장면부터 **200줄에 걸쳐 대사가 한 칸씩 밀려** 있었습니다. 말한 사람과 대사가 어긋나 있었으니, 번역이 어색한 정도가 아니라 장면이 통째로 읽히지 않는 상태였습니다.

원인은 `【近藤】「覚悟しておくんだな！」` 한 줄의 번역이 아예 비어 있었던 것입니다. 그 뒤로 모든 줄이 한 칸씩 앞으로 당겨졌고, 마지막에 `…………` 한 줄이 남아 아귀를 맞추고 있었습니다. 재번역 작업을 나눠 처리할 때 그 묶음 안에서 한 줄이 빠진 채 만들어진 것입니다.

빠진 한 줄을 채우고 200줄을 제자리로 되돌렸습니다.

이 문제는 눈으로 찾은 게 아니라 **줄 구조로 찾았습니다.** 번역이 원문의 줄바꿈을 그대로 지키고 있어서, 네 줄짜리 일본어 대사는 네 줄짜리 한국어 대사입니다. 이 모양은 번역해도 남기 때문에 전체 9,626행을 이 방식으로 훑었고, 밀린 구간은 이 한 군데뿐이었습니다.

## 이름 세 개

| | 지금까지 | 바로잡음 | 근거 |
|---|---|---|---|
| `白川一朗` | 시라카와 **이치리** | 시라카와 **이치로** | 게임 안 후리가나 `一朗《いちろう》` |
| `白川真二` | 시라카와 **사토루** | 시라카와 **신지** | `白川悟《しらかわさとる》`는 다른 인물입니다 |
| `西島` | **도요시마** | **니시지마** | 西島의 읽기가 아니었습니다 |

`白川真二`와 `白川悟`는 원문이 깨져 있던 탓에 **두 사람이 한 이름으로 합쳐져** 있었습니다. 이제 나뉩니다.

## 원문 글자표 전수 검증

이름표가 문제를 알려줬습니다. `斉藤佳代`(v2.3)를 확인하다 보니, 글자표를 만든 두 방법 중 **나중의 정확한 쪽(글리프를 직접 그려서 판독)을 앞선 추정이 덮어쓰고** 있었습니다.

그래서 글자표에서 한 번도 눈으로 확인되지 않은 **1,064자를 전부 렌더링해서 판독**했습니다. **263자가 틀려 있었습니다.**

고치면 이런 문장들이 돌아옵니다.

```
彩業元      → 従業員        駅口     → 樋口
朝等        → 朝露          白川一利 → 白川一朗
応接室が況む → 応接室が埋まる  猪っています → 祈っています
引っ込み思司 → 引っ込み思案   注しく指導  → 厳しく指導
観何度物    → 観葉植物       白川不係産 → 白川不動産
```

`水無月月司`라는 있을 수 없는 이름은 `水無月幸司`였습니다.

**번역은 대부분 이미 맞았습니다.** 원문이 `彩業元`이어도 번역자는 문맥으로 읽어 `종업원`이라고 옮겼고, `駅口`도 `히구치`였습니다. 사람이 문맥으로 메울 수 없는 것은 이름뿐이었고, 그래서 고친 것도 이름 세 개입니다.

두 글자(1281, 1286)는 16×16 픽셀에서 어떻게 확대해도 읽히지 않아, **추측하지 않고 그대로 두었습니다.**
