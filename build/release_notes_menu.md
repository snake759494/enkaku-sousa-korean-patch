> **이것은 실험판입니다. 기존 패치를 대체하지 않습니다.**
> 세이브 화면의 `セーブ`·`削除`를 한글로 바꾸려면 **실행 파일을 교체**해야 하고, 그러면 게임이 부팅되지 않을 수 있습니다. 평소 쓰실 것은 [v3.2](https://github.com/snake7594/enkaku-sousa-korean/releases/tag/v3.2)입니다.

## 무엇이 다른가

```
セーブ → 저장        削除 → 삭제
```

이 두 낱말은 그림이 아니라 **실행 파일 안의 문자열**이라, 지금까지 손대지 못했던 것입니다.

## 왜 부팅되지 않을 수 있는가

PSP가 싣는 `EBOOT.BIN`은 **암호화되어** 있습니다. 그 안을 고칠 방법이 없으므로, 같은 디스크에 들어 있는 **평문 사본(`BOOT.BIN`)을 고쳐서 `EBOOT.BIN` 자리에 넣었습니다.**

- **CFW·PPSSPP**는 평문 ELF를 받아들입니다 → 동작할 가능성이 높습니다
- **정품 펌웨어**는 받아들이지 않습니다 → 부팅 실패

ISO 배치는 건드리지 않았습니다. 평문 ELF가 348바이트 작아서 뒤를 0으로 채워 원래 크기(1,194,496바이트)에 맞췄고, 파일 위치와 크기가 그대로라 v1.1에서 겪은 `C1-2858-3`과 같은 문제는 생기지 않아야 합니다. **다만 확인된 것은 아닙니다.**

## 어떻게 찾았는가

역어셈블로 풀었습니다. 세이브 메뉴를 그리는 코드(`0x88814cc`)가 문자열 포인터를 읽어 화면 `(212,116)`·`(212,134)`에 그리고, 그 해독기(`0x884be84`)의 첫 다섯 줄이 답이었습니다.

```
lw   $v1, [0x8a02c14]
slt  $v1, $a0, $v1         ; 문자열 주소가 그보다 앞이면
bnez → $a3 = 0x88EA760     ;   실행 파일 안의 글꼴
else → $a3 = [0x89f5e18]   ;   stream1 의 글꼴
```

**글꼴이 둘이었습니다.** 대사는 `stream1` 것을, 실행 파일 안의 문자열은 실행 파일 안의 것을 씁니다. "메뉴가 대사 글꼴을 이상하게 가리킨다"고 본 그동안의 진단이 처음부터 틀렸던 것입니다.

인코딩도 확정했습니다. 가나는 평범한 Shift-JIS이고, 한자는 Shift-JIS가 비워 둔 `0x8800`부터를 사유 영역으로 씁니다.

```
index = ((code - 0x8800) >> 8) * 253 + (code & 0xFF)
glyph = base + (index >> 1) * 256
```

`253`이 그동안 상수 검색에 걸리지 않은 이유도 나왔습니다 — 컴파일러가 `((x << 6) - x) << 2) + x` 로 풀어 놓았습니다.

검증했습니다. 이 글꼴에서 `325·326 = 削除`, `245·246 = 存在`, `154·334 = 上書`, `0·1 = 黙秘` — 예측 넷이 전부 맞습니다.

## 왜 두 낱말뿐인가

이 글꼴은 **872자**이고, 실행 파일의 모든 문자열을 읽어 보니 **아무도 쓰지 않는 슬롯이 5개**뿐이었습니다. `저`·`장`·`삭`·`제` 넉 자가 겨우 들어갑니다.

문자열 길이도 제자리에서 늘릴 수 없습니다. 다행히 `セーブ`(5바이트)와 `저장`(4+종료 1), `削除`(5)와 `삭제`(5)가 정확히 맞아떨어져 포인터를 건드리지 않았습니다.

같은 화면의 `黙秘：`·`人物：`·`場所：`·`証拠：`는 여덟 자가 더 필요해서 자리가 없습니다.
