```
certutil -hashfile "Enkaku Sousa Shinjitsu eno 23nichikan.iso" MD5
```

```

원본 MD5    9f9bb5eec3d2c37f184955b591923e1c
```

```
xdelta -d -s "Enkaku Sousa Shinjitsu eno 23nichikan.iso" Enkaku_Korean_v3.4.xdelta Enkaku_Korean.iso
```

```
결과 크기   739,835,904 바이트 (원본과 동일)
```

v3.3의 내용은 전부 포함되어 있습니다. 이전 버전에서 갱신하는 경우에도 **원본 ISO에 적용**하십시오.

## 무엇이 바뀌었나

**튜토리얼 21쪽** — 게임을 처음 할 때 뜨는 `解説` 화면입니다.

```
尋問について     6쪽 → 심문에 관하여
調査について     3쪽 → 조사에 관하여
調査依頼について 4쪽 → 조사 의뢰에 관하여
辞典について     3쪽 → 사전에 관하여
クルーについて   3쪽 → 단서에 관하여
情報集約について 2쪽 → 정보 집약에 관하여
```

**장면 배너 12장** — `尋問開始`·`尋問終了`·`前日の調査報告`·`報告終了`.

용어는 기존 패치와 맞췄습니다. `クルー`는 **단서**, `心証`은 **심증**, `黙秘権`은 **묵비권**입니다.

## 어떻게 열었는가

두 가지가 막고 있었습니다.

**LZ11을 바이트로 훑고 있었습니다.** 스트림 하나를 풀고 압축 길이만큼 건너뛰면 패딩 한가운데 떨어져 나머지를 잃습니다. 실제로는 `0x800` 정렬 블록의 연속이고 블록마다 `0x40` 헤더(MD5 16바이트 + 제로)가 붙습니다. 경계를 따라 걸으니 `0002`가 3%에서 566 스트림이 됐습니다.

**픽셀이 연속된 런이 아니었습니다.** 오프셋 16부터 타일 배열입니다.

```
u16 tile_x, u16 tile_y, 12바이트, 그리고 tile_w x tile_h, 16x8 스위즐
```

타일 앞 16바이트를 그림으로 그리고 있었으니 매 타일마다 어긋났습니다. 그리고 오프셋 12의 워드는 시작 위치가 아니라 **타일 개수**였습니다.

```
배너     16 + 16 x 1040  = 16,656  = 레코드 길이
배경     16 + 120 x 1040 = 124,816
512x512  16 + 240 x 1040 = 249,616
```

타일마다 자기 좌표를 들고 있어서 빈 타일을 빼도 제자리에 놓입니다.

## 안전장치

레코드를 **읽었다가 그대로 다시 쓰면 바이트가 일치하는지** 먼저 확인하고, 통과한 것만 건드렸습니다. 통과하지 못한 29장은 손대지 않았습니다 — 재현할 수 없는 것을 덮어쓰면 조용히 망가집니다.

블록 헤더는 패딩까지 포함한 구간의 MD5라서 다시 계산했습니다. 압축본은 원래 길이에 맞춰 0으로 채웠으므로 **뒤따르는 블록은 한 바이트도 움직이지 않습니다.** 아카이브 크기도 그대로입니다.

## 손대지 않은 것

- **장소 이름표 19장** — 각 그림이 글자 조각만 담고 있어 무엇을 말하는지 확정할 수 없었습니다. 추측해서 넣지 않았습니다.
- **재현되지 않는 29장** — 타일 배치가 아직 안 맞습니다.
- **타이틀 화면 문구** — `0001~0004` 어디에도 없습니다. 남은 후보는 동영상입니다.
