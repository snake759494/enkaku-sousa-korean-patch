## 무엇이 잘리고 있었는가

보내주신 스크린샷 두 장에서 상자를 직접 쟀습니다.

```
글자는 x=203 에서 시작하고 화면은 480 넓이  ->  277 픽셀
한글 한 글자가 16 픽셀                      ->  16.5 글자 = 33 반각
줄 간격 25 픽셀, 첫 줄 y=44, 하단 바 y=248  ->  8 줄
```

잘린 두 줄은 **34반각과 35반각**이었습니다. 딱 한두 글자가 넘쳤던 것입니다.

## 왜 여태 몰랐는가

파이프라인에는 이미 줄 맞춤 단계가 있었는데, **글자 수 19자**로 세고 있었습니다. 한글 19자는 38반각이라 상자보다 넓습니다. 문제의 줄은 18자였으니 그 검사를 그냥 통과했습니다.

원문을 기준으로 삼아 보려고도 했습니다 — 일본어는 정의상 상자에 들어맞으니까요. **틀렸습니다.** 일본어 줄은 이 셈법으로 66반각까지 가는데, 분포에 끊긴 데가 없고 스크립트 구간별로 몰리지도 않습니다. 즉 **일본어 글꼴은 비례폭**이라 가나가 16픽셀보다 훨씬 좁게 나갑니다. 글자 수를 세는 것으로는 한글이 얼마나 필요한지 알 수 없습니다. 실측한 33이 유일한 기준입니다.

## 무엇을 고쳤는가

**459행**을 다시 나눴습니다.

- 넘친 부분만 아래로 밀고, 밀린 줄이 또 넘치면 계속 아래로 이어 보냅니다. 들어맞고 있던 줄바꿈은 그대로 둡니다.
- 8줄을 넘긴 행은 다시 짭니다. 상자 밖으로 나가던 행이라 손댈 수밖에 없습니다.
- **글자는 하나도 늘거나 줄지 않았습니다.** 공백과 줄바꿈만 움직였습니다.

예외가 둘 있습니다. 비명 두 행(`꺄아아…!!`, `그아아…악!!!`)은 띄어쓸 자리가 없어서 반복 글자를 몇 개 줄여 맞췄습니다.

```
【코우지】
(……같은 식으로 상쾌하게 인사하며      <- 34반각, 「며」가 잘림
들어와 주면 좋으련만.
안 그래도 분위기가 살벌한데.)
```

```
【코우지】
(……같은 식으로 상쾌하게              <- 25
인사하며 들어와 주면 좋으련만.         <- 30
안 그래도 분위기가 살벌한데.)          <- 29
```

## 손대지 않은 것

심문 선택지(`［피해자와 누마사키 에이타로의 관계］` 등) 여섯 줄이 33반각을 넘습니다. 그 화면 스크린샷이 없어서 **선택지 목록의 상자 폭을 모릅니다.** 대사 상자와 같다고 단정하고 문구를 줄이기보다, 그대로 두었습니다. 그 화면에서도 글자가 잘린다면 알려주십시오.
