> ### v3.3과 v3.4를 쓰고 계시다면 지금 바꿔 주십시오.
> 그 두 판은 **대사가 전부 다른 글자로 나옵니다.** 제가 낸 회귀입니다. 이 판에서 고쳤습니다.

## 무엇이 잘못됐었나

v3.3에서 빌드의 기준 스트림을 바꿨습니다. 배포본과 글꼴 구역이 일치하는 쪽으로 맞춘 것인데, **슬롯 표를 같이 바꾸지 않았습니다.** 슬롯 표는 글꼴에 딸린 것입니다.

```
korean_slots_full_clean       .=0  지=1  이=2  코=3  ,=4  다=5 …
korean_slots_retranslated_v2  지=0  이=1  .=2   코=3  우=4  아=5 …
```

같은 글자가 다른 번호를 답니다. 그래서 한 글자도 빠짐없이 **제대로 생긴 한글이, 전부 엉뚱한 글자로** 그려졌습니다.

```
【코우지】               →   【겼인】
씨야 론맞을 적제. 건사
```

빌드는 아무 이상을 보고하지 않았습니다. 마커도 맞고 참조도 풀리고 아카이브 크기도 그대로였습니다. 검사하던 것 중에 **글자가 무엇으로 읽히는지 보는 검사가 없었습니다.**

배포본 스트림을 두 표로 각각 해독해 보면 결정적입니다.

```
korean_slots_full_clean       →  돼시외.(타었.버신
korean_slots_retranslated_v2  →  새로운 정보를 입수     <- 이쪽
```

## 이제 검사합니다

`verify_dialogue.py`를 넣었습니다. 완성된 ISO에서 스트림을 꺼내 **빌드와 같은 인코더로 각 행을 인코딩해 그 바이트가 실제로 들어 있는지** 확인합니다.

```
v3.5  294 / 294   통과
v3.4    0 / 294   실패   <- 잡힙니다
v3.2  294 / 294   통과   (정상이던 판)
```

덤으로, 표가 맞으니 **인코딩 실패 행이 107개에서 0개**로 줄었습니다. 그 107행은 v3.3·v3.4에서 일본어로 남아 있었습니다.


```
xdelta -d -s "Enkaku Sousa Shinjitsu eno 23nichikan.iso" Enkaku_Korean_v3.5.xdelta Enkaku_Korean.iso
```

```

결과 MD5    bf7ca7fe675ecec4e9e3f5824785449b
```

**반드시 원본 ISO에 적용하십시오.** v3.3이나 v3.4에 덧씌우지 마십시오.
